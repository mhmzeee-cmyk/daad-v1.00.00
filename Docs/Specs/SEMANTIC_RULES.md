## R-01 — بنية البرنامج: عام مقابل تنفيذي (C++)

- **FACT** (`Compiler.cpp:18-27`): `isGlobalDeclaration` = Function|Class|Struct|Enum|Namespace|Template|Import|Export → تُصدر في النطاق العام (header للبعض + source). أي شيء آخر → يُجمع في `executable` ويُغلف بـ `beginMainBody/endMainBody` → `int main()`.
- **القاعدة:** ملف بلا عبارات تنفيذية يُنتج مكتبة (header+source بلا `main`)؛ ملف بعبارات تنفيذية يُنتج `main` تحتويها بالترتيب.
- **JS المقابل** (`dhad-codegen.js:36-69`): `collectDeclarations` (Function|Class|Struct فقط) → `emitRuntime` → `emitClasses` → `emitFunctions` → `emitGlobals` → جسم رئيسي. `Import/Export/Template` تُلغى (`:401-403`).

## R-02 — خريطة الأنواع (C++)

- **FACT** (`CodeGen.cpp:57-106`):
  ```
  صحيح→int، عشري→double، حرف→char، منطقي→bool، فراغ→void، نص→std::string، تلقائي→auto
  صحيح[]→vector<int>، نص[]→vector<string>، عشري[]→vector<double>، حرف[]→vector<char>، منطقي[]→vector<bool>
  نوع[][]...→vector<vector<...>> تكراريًا (:92-104)
  غير المعروف → يُمرر نصًا كما هو (:105) — أنواع المستخدم (صفوف) بلا تهيئة صفرية (:237-255)
  ```
- **القاعدة:** الأنواع السبعة الأساسية + المصفوفات إجبارية التطابق حرفيًا؛ أي نوع آخر يُفترض نوع مستخدم (صف) ويُعلن بلا `= 0`.
- **JS:** الأنواع غير منمطة runtime (`var`/`const` فقط — `emitVarDecl:433-443`) — التوافق اسمي لا نوعي.

## R-03 — التهيئة الافتراضية

- **FACT** (`Parser.cpp:573-574`): إعلان بلا `=` → `VarDecl(type,name,Number(0.0))`.
- **FACT** (`CodeGen.cpp:240-267`): `Number(0)` لنوع مستخدم → إعلان بلا تهيئة (لأن `= 0` غير صالح)؛ `Number(0)` لنص → يُستبدل `""`؛ `{}` (مصفوفة فارغة) لنوع قياسي → ترقية `vector<T>`.
- **القاعدة:** `صحيح س ؛` ≡ `صحيح س = 0 ؛` (عدا المستخدم والنص والمصفوفة الفارغة كما أعلاه).

## R-04 — أسماء المستخدمين مقابل المكتبة (منع التصادم)

- **FACT** (`Compiler.cpp:52-62` + `CodeGen.cpp:150-166`): تُجمع أسماء `FunctionDeclAST` المعرفة بالمصدر في `userFns`، ثم تُرفع `using daad::stdlib::name` **انتقائيًا** لكل اسم في `stdlibExportedNames` (34 اسمًا — `CodeGen.cpp:110-148`) **ما لم** يعرّفه المصدر (تخطي `m_userFunctionNames.count(name)`).
- **القاعدة:** تعريفك لدالة باسم مكتبة (مثل `طول`) **يحجب** الـ `using` التلقائي لها — لا تصادم بنية.

## R-05 — تعريف الدوال: التوقيع والافتراضات

- **FACT C++** (`Parser.cpp:1003-1047`): الافتراضي للإرجاع `فراغ`؛ المعامل المفرد بلا نوع → `صحيح` (`parseParam:1102-1104`)؛ الفارغ `[]` → `فراغ` فارغ (`:1074-1078`)؛ `الاسم:النوع` و`النوع الاسم` كلاهما مقبولان.
- **FACT JS** (`dhad-parser.js:522-575`): الافتراضي `'void'` نصًا؛ المفردة → `صحيح`؛ القيم الافتراضية `= expr` محفوظة (`params[{type,name,defaultValue}]`) وتُصدر كـ `if(p===undefined)` (`emitFunctions`).
- **القاعدة:** `دالة f(أ)` ≡ `دالة f(صحيح أ) -> فراغ` في الطرفين.

## R-06 — الأعضاء والطرق: الشكلان المقبولان في C++

- **FACT** (`Parser.cpp:1126-1268`):
  - عضو: `النوع الاسم ؛` (Form-1 `:1196-1224`) أو `الاسم : النوع ؛` (Form-2 `:1162-1194`)؛ `؛` اختيارية بسطر جديد (`:1186-1188,:1220-1224`).

- **القاعدة:** اكتب الأعضاء بأي الشكلين؛ اكتب الطرق بصيغة النوع-أولًا حصرًا.

## R-07 — الصفوف المعروفة كأنواع (C++)

- **FACT** (`Parser.cpp:161-163` + `:1132` + `isKnownTypeName:1049-1058`): اسم الصف بعد تعريفه يُسجل في `m_knownClassNames` ويُقبل كنوع (`النوع[]` تُجرد للمقارنة) في `parseParam` و`parseVariableDeclaration` عبر المعرف.
- **القاعدة:** عرّف الصف **قبل** استخدامه نوعًا — الترتيب مهم (لا رفع hoisting للأنواع في C++).

## R-08 — الأسماء المركبة بمسافات (C++ فقط)

- **FACT** (`Parser.cpp:165-172` للمتغيرات + `:1008-1013` للدوال + `:400-404` للابتدائي): توكنات `IDENTIFIER` متتالية تُدمج بمسافة (`name += " " + text`) ثم تُطهّر `_` في التوليد (`sanitizeIdent:9-15`: بادئة `.` تُزال، مسافة → `_`).
- **القاعدة:** `إضافة_ خاصية` اسم واحد قانوني في C++ يُولد `إضافة__خاصية` (بمسافة→_). JS بلا دمج مماثل مثبت (أسماء مفردة) — تجنب المسافات للتوافق.

## R-09 — الكلمات كأسماء (الهروب الاسمي)

- **FACT C++** (`Parser.cpp:236-283`): أي `TOKEN_KEYWORD` لم يطابق فرعًا لغويًا تُعامل كاسم متغير/استدعاء (`= | op= | ( | . =`)؛ `parseVariableDeclaration:532-534` و`parseParam` تقبلان KEYWORD أسماءً (مثل `س/ص`)؛ `parsePrimary:450-457` أي كلمة → استدعاء أو متغير.
- **FACT JS** (`dhad-parser.js:64-86` `isName/expectName`: أي `IDENTIFIER` أو `KW_*` اسم صالح).
- **القاعدة:** الكلمات المحجوزة أسماء احتياطية قانونية (عدا مواقع العبارات) — ميزة توافق مقصودة، ليست ثغرة.

## R-10 — المصفوفات: الفهرسة المتسلسلة (C++)

- **FACT** (`Parser.cpp:203-227` + `parsePrimary:410-423` + `CodeGen:582-604`): `a[i][j][k]` تُبنى كسلسلة `base` (آخر قوس هدف، ما قبله base) وتُولد `base[idx]`.
- **القاعدة:** الفهرسة المتسلسلة قانونية في C++ بدلالة `base[idx]`. JS مفردة (بلا `base` في `dhad-ast.js:92`) — تجنب `a[i][j]` للتوافق حتى الإصلاح.

## R-11 — السلاسل النصية في `+` و`switch` (C++)

- **FACT** (`CodeGen.cpp:200-206`): `حرفي + تعبير-نصي` يُلف الحرفي `std::string("...")` لتفادي `const char* + string` الخاطئ (يُكتشف عبر `std::string|اقتطع|فصل(|تحويل` في الطرف الأيمن).
- **FACT** (`CodeGen.cpp:372-425`): `switch` بقيم نصية → سلسلة `if-else`؛ بعددية → `switch+break` تلقائي.
- **القاعدة:** جمع النصوص وتبديلها آمنان في C++ لهذه الحالات المحصورة فقط.

## R-12 — الطي الثابت (الدلالة المحفوظة والمكسورة)

- **FACT** (`Optimizer.cpp:38-54`): يُطوى `Number op Number` لـ `+ - * / %` فقط (`%` بتحويل int) ويستهلكها `CodeGen:184-185` (تُطبع `int(folded)` دائمًا!).
